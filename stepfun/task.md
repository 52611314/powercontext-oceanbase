## 一、题目背景

在浏览器中运行 AI 模型，可以让用户在自己的设备上完成文档向量化。将端侧推理与 seekdb 的数据存储和检索能力结合，可以构建轻量的个人知识库应用。

本题考察端侧模型运行、量化、推理后端选择以及数据库检索的综合工程能力。参赛者需要完成“导入语料 → 本地向量化 → 写入 seekdb → 混合检索”的完整流程，并在保证检索质量的前提下进行基础性能优化。本题不要求训练模型。

## 二、题目内容

### 2.1 实现迷你知识库应用

用户可以导入一批文本文档，应用在浏览器本地将内容编码为向量，并将向量、原文和元数据写入 seekdb。用户输入查询后，应用在本地生成查询向量，通过 seekdb 完成向量与全文混合检索，展示排序后的结果及对应原文。

文本知识库为基础要求，图片内容支持可作为扩展。

### 2.2 端侧推理与模型量化

1. 使用 Transformers.js、ONNX Runtime Web 等端侧运行时，在用户设备的浏览器中执行 embedding 推理。文档向量化和查询向量化均须在本地完成。
2. 模型可自由选择，例如适合端侧运行的 all-MiniLM-L6-v2、bge-small 等，但必须为可公开获取的开源模型，并在技术说明中注明来源与版本。
3. 对 embedding 模型采用 **INT8 或 FP16** 方案，说明处理方式，并报告量化前后的模型体积、压缩比及检索质量变化。
4. **优先使用 WebGPU**，显式配置对应推理后端；运行环境不支持 WebGPU 时，自动降级到 **WASM**，并在界面中明确提示当前使用的后端。

### 2.3 seekdb 存储与混合检索

1. 通过 seekdb-js 接入 seekdb，创建集合或表，保存向量、原文及文档 ID 等元数据。数据库可采用嵌入式或本地 server 方式部署。
2. 实现向量与全文混合检索，检索处理由 **seekdb 完成**，不得在客户端分别获取两路结果后自行拼合来替代数据库混合检索。
3. 正确处理数据写入和索引刷新，确保新导入的文档在刷新完成后能够被检索到。
4. 管理知识库的增量写入、集合与会话状态，保证连续导入和切换操作后的检索结果与当前知识库一致。

### 2.4 基础性能优化

围绕 embedding 批处理、模型加载、推理延迟、数据库检索延迟和索引刷新策略开展优化，并提供优化前后的实测结果。性能提升应建立在功能完整、检索质量不明显下降的基础上。

### 2.5 通用要求

+ 应用可在主流现代浏览器 **Chrome / Edge 最新版**中运行。
+ **禁止调用云端推理 API**。模型文件下载或本地加载不改变推理位置要求，实际计算必须发生在用户设备。
+ 禁止预先在服务端算好向量或检索结果后回放，禁止将远程推理伪装为端侧推理。
+ 向量和文档的存储、检索必须使用 seekdb，不得使用其他数据库或客户端内存检索替代。

## 三、验收标准

### 3.1 功能与质量

| 检查项        | 要求                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 完整流程      | 可导入文本、生成向量、写入 seekdb、输入查询并展示排序后的检索结果            |
| 本地推理      | 文档与查询的 embedding 均在浏览器本地计算，无云端推理 API 调用               |
| 模型量化      | 使用 INT8 或 FP16 方案，提供模型来源、量化方式、体积对比及质量变化           |
| 后端与降级    | 支持时优先使用 WebGPU；不支持时自动降级至 WASM，并明确提示，核心流程仍可运行 |
| seekdb 数据层 | 向量、原文及元数据存于 seekdb，向量与全文混合检索在 seekdb 中完成            |
| 状态与刷新    | 支持增量导入，索引刷新后新增内容可检索，集合与会话状态正确                   |
| 可复现性      | 按提交的说明可启动应用及数据库，并完成上述操作                               |

调用云端推理 API、回放服务端预计算结果，或绕过 seekdb 完成存储与检索，均不符合本题要求。

### 3.2 性能与质量测试方法

1. **固定测试条件**：使用相同设备、浏览器版本、语料和查询集，记录模型版本、精度、推理后端、批大小及 seekdb 配置。
2. **对比模型体积**：按同一口径统计实际模型文件的总体积，分别记录量化前后大小，计算 `压缩比 = 量化前体积 / 量化后体积`。压缩效果以实测为准。
3. **检查检索质量**：在相同评测集上对比量化前后的质量，注明评测方法。可使用 Recall@K、nDCG@K 等指标，说明变化幅度，避免仅凭主观展示判断质量。
4. **分阶段计时**：分别记录模型下载与加载、文档向量化、写入与索引刷新、查询向量化、seekdb 检索耗时，同时报告用户提交查询到结果可展示的端到端延迟。
5. **区分首次与后续请求**：首次加载和预热后的性能分开报告。建议重复测试，保留原始数据并报告中位数，不能只选择最快一次。
6. **验证降级路径**：分别测试 WebGPU 可用与不可用的环境，确认后端选择、界面提示及 WASM 下的检索流程。

建议在实验结果中列出以下信息：

| 配置                 | 模型体积 | 向量化吞吐 | seekdb 检索延迟 | 端到端查询延迟 | 检索质量     |
| -------------------- | -------- | ---------- | --------------- | -------------- | ------------ |
| 量化前基线           | 实测值   | 实测值     | 实测值          | 实测值         | 指标与结果   |
| INT8 / FP16 + WebGPU | 实测值   | 实测值     | 实测值          | 实测值         | 同一指标结果 |
| INT8 / FP16 + WASM   | 实测值   | 实测值     | 实测值          | 实测值         | 同一指标结果 |

比较单项优化时，应保持其他条件一致；技术说明需注明设备、数据规模及计时范围。

## 四、提交材料

### 4.1 可运行的 Web 应用

提供可本地启动的应用，或可访问的在线地址。说明浏览器要求、依赖安装和启动步骤；seekdb 使用嵌入式方式，或随应用提供本地 server 的启动脚本与连接配置。

应用应能演示文档导入、向量化进度、检索结果和当前推理后端。在线部署的前端同样需要满足用户设备本地推理的要求。

### 4.2 完整源码

提供应用源码、依赖与配置、模型获取及量化步骤、seekdb 集合或表结构与索引配置，以及用于复现测试的数据或数据生成方式。

### 4.3 一页技术说明

+ **模型与量化**：模型来源和版本、INT8 / FP16 方案、量化前后体积与压缩比、检索质量变化。
+ **端侧运行**：运行时、WebGPU 选择方式、WASM 自动降级策略及验证结果。
+ **seekdb 使用**：集合或表结构、向量与全文混合检索方式、增量写入及索引刷新策略。
+ **状态与优化**：集合/会话状态管理、批处理与其他优化点、关键性能对比结果。

技术说明之外可附测试日志和详细复现步骤，实验结果应来自提交应用的实际运行。
