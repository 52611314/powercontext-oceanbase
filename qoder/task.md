## 一、题目背景

整理文献要翻几十篇论文，复习时找不到上学期的笔记，周报总要从聊天记录里一条条拼。学习、科研和工作中，总有一些重复又耗时的环节值得被改造。

Qoder 是面向真实开发工作的智能体编程平台。开发者用自然语言描述需求，Qoder 可以完成需求拆解、编码、调试和部署。

本题以工作提效和学习科研为主题。参赛者可以从自己或身边同学、同事的一个真实痛点出发，用 Qoder 开发项目解决它，并结合 seekdb 或 PowerContext 实现核心功能。项目完成后，参赛者使用 Qoder Sites 发布项目网站，作为作品展示和评审体验的入口。项目形式不限，应用、工具、插件、Agent 均可。

## 二、题目内容

### 2.1 用 Qoder 开发项目

项目的主要开发工作必须在 Qoder 中完成。桌面端、IDE、JetBrains 插件和 CLI 均可使用。

参赛者需保留开发过程记录，说明 Qoder 在需求拆解、编码、调试等环节中完成了哪些工作。仅用 Qoder 发布网站而项目在其他工具中开发的作品，不符合本赛道要求。

### 2.2 技术结合要求

| 组成                         | 要求与作用                                                                           |
| :--------------------------- | :----------------------------------------------------------------------------------- |
| Qoder（必选）                | 承担项目的主要开发工作，并通过 Qoder Sites 发布项目网站                              |
| seekdb（至少选择一种）       | 为项目提供数据存储、查询与检索能力，例如知识库检索、内容匹配或业务数据查询           |
| PowerContext（至少选择一种） | 为项目提供记忆与上下文能力，例如保存用户偏好、任务进展或历史互动，并在后续使用中复用 |

seekdb 支持向量、全文和结构化条件结合的混合检索，提供嵌入式、服务端和 Docker 等部署方式，兼容 MySQL 协议，参见 [seekdb 项目说明](https://github.com/oceanbase/seekdb/blob/master/README_CN.md)。PowerContext 是面向 AI Agent 的开源上下文服务，支持 HTTP API、MCP 和 Python SDK 接入，参见 [PowerContext 项目说明](https://github.com/oceanbase/powercontext/blob/master/README_CN.md)。同时使用两者的作品应说明各自分工。

指定技术必须在项目功能中实际发挥作用。参赛者应展示数据或检索结果如何用于项目流程，或记忆如何被保存并在后续使用中复用。仅安装组件或测试连接，不满足这一要求。

### 2.3 用 Qoder Sites 发布项目网站

项目完成后，在 Qoder 中通过 Sites 创建并发布项目网站，并将可见范围设置为「任何人都可访问」。企业版账号无法设置公开访问，请使用个人账号发布。

项目网站应包含项目简介、解决的问题、核心功能、演示视频或截图、代码仓库链接，以及体验入口（如有）。有使用效果数据的项目，建议在网站上一并展示。项目网站用于展示作品和提供评审入口，评审对象是项目本身，网站不单独评分。

### 2.4 使用效果（鼓励提交）

本题鼓励参赛者把项目交给真实用户使用，并记录使用效果。效果数据不是基础验收的必要条件，但会作为评价维度之一。

| 内容     | 示例                                                       |
| :------- | :--------------------------------------------------------- |
| 使用规模 | 有多少同学或同事使用过，累计使用次数，持续使用了多长时间   |
| 提效结果 | 使用前后的对比，例如整理一次文献从 2 小时缩短到 20 分钟    |
| 用户反馈 | 问卷结果、用户评价截图、收到的改进建议，以及据此做出的迭代 |

数据须真实可核对，并附上来源，例如访问统计截图、使用日志、问卷导出结果。项目网站部署在 Qoder Sites 上时，可在站点的「访问统计」中查看访问次数和独立访客。展示用户反馈时，请隐去姓名、联系方式等个人信息。

### 2.5 参考方向

以下只是示例，欢迎从自己的真实需求出发设计项目。

| 方向           | 示例                                                                                  |
| :------------- | :------------------------------------------------------------------------------------ |
| 文献与资料检索 | 把论文、课程笔记或实验记录导入 seekdb，按语义和关键词混合检索，快速找到相关段落和出处 |
| 学习助手       | 用 PowerContext 记住每个人的薄弱知识点和复习进度，做一个越用越懂你的复习教练          |
| 科研流程工具   | 自动整理实验数据、生成组会汇报初稿，或追踪领域内的新论文并按研究方向推送              |
| 办公提效       | 汇总会议纪要、聊天记录和待办，自动生成周报；或用 seekdb 搭一个团队内部的文档问答助手  |
| 多 Agent 协作  | 让多个 Agent 通过 PowerContext 共享任务上下文，分工完成调研、写作或数据整理           |

## 三、验收标准

### 3.1 基础验收

满足以下条件，即达到基础要求：

1. **网站可访问。** 项目网站通过 Qoder Sites 发布，未登录状态下也能打开。
2. **项目能够运行。** 评审按运行说明完成配置后，项目能够启动，并可按验证样例体验主要功能。
3. **Qoder 开发可核对。** 开发记录能够体现项目的主要功能由 Qoder 参与完成。
4. **技术结合有效。** seekdb 或 PowerContext 在项目功能中实际发挥作用，可通过查询结果、检索记录或记忆读写记录核对。

截图、录屏和运行日志可作为验证材料，但仍需提供可运行的项目和明确的复现步骤。

### 3.2 评价维度

| 维度           | 关注内容                                                        |
| :------------- | :-------------------------------------------------------------- |
| 实用价值       | 项目是否针对工作或学习科研中的真实痛点，解决方式是否有效        |
| 使用效果       | 是否有真实用户使用，提效结果和用户反馈是否有可核对的数据支撑    |
| 完成度与体验   | 主要流程是否完整、顺畅，项目是否实现了所描述的功能              |
| 技术结合       | seekdb、PowerContext 的使用是否合理，是否对项目功能产生实际帮助 |
| Qoder 开发实践 | 开发记录是否清楚展示了 Qoder 在项目中的作用                     |
| 工程质量       | 代码结构是否清晰，依赖与配置是否齐全，评审能否顺利复现          |

具体评分细则、权重及评测环境由赛事后续公布。

## 四、提交材料

| 材料                     | 要求                                                                                           |
| :----------------------- | :--------------------------------------------------------------------------------------------- |
| 项目网站网址             | Qoder Sites 发布后的完整访问网址，可见范围为「任何人都可访问」                                 |
| 代码仓库                 | 完整项目源码，公开仓库或向评审开放访问权限                                                     |
| 运行说明                 | 运行环境、依赖版本、seekdb 或 PowerContext 的部署与接入方式、从安装到启动的完整步骤            |
| 验证样例                 | 至少一组可按步骤执行的样例，包含初始数据、输入、操作步骤、预期结果，以及指定技术发挥作用的记录 |
| Qoder 开发记录           | 关键开发环节的 Qoder 对话截图或录屏，并附 Qoder 账号 UID，用于核对站点归属及使用记录           |
| 使用效果材料（鼓励提交） | 使用人数、使用次数、提效对比和用户反馈，并附访问统计截图、使用日志或问卷结果等来源             |

配置示例使用占位值，不提交真实 API Key、密码或其他凭据。复用开源代码或数据时，注明来源及所作改动。

## 五、提交方式

1. 登录大赛测试平台，进入 Qoder 赛题的提交入口。
2. 填写项目网站网址、代码仓库地址和 Qoder 账号 UID，并上传其余材料。
3. 提交前用浏览器无痕窗口打开项目网站，确认可以正常访问。

完整流程为：用 Qoder 开发项目 → 接入 seekdb 或 PowerContext → 用 Qoder Sites 发布项目网站 → 整理提交材料 → 提交到测试平台。

评审结束前，请勿暂停或删除已提交的站点。发布后修改网站内容，需要再次点击「发布」才会更新线上版本。
