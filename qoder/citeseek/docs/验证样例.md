# 验证样例

> 目标：评审按下面 8 步在 10 分钟内跑通主流程，并核对 seekdb 的实际作用。
> 初始数据：`samples/papers/` 下 3 份中文示例 PDF（自撰讲义），无需联网。

## 0. 启动

```bash
cd qoder/citeseek/deploy
docker compose up -d --build
curl http://127.0.0.1:8080/api/ready
```

预期：

```json
{"ok":true,"checks":{"seekdb":"ok","embedding":"ok"},"dim":512}
```

## 1. 导入资料

打开 <http://127.0.0.1:8080/library>，把 `samples/papers/` 下 3 个 PDF 一次拖入上传框。

预期：3 篇文献依次从「等待中」变为「已索引」，每篇 2 页、6–7 个文本块；重复上传同一文件会提示「已存在」。

## 2. 混合检索

进入「混合检索」，输入：

```
长上下文推理时显存占用怎么降低？
```

保持「混合检索」，点击检索。

预期：

- 返回 10 条结果，其中前 3 条来自《大模型推理优化讲义》，页码 1；
- 结果卡片同时出现「全文 #n」和「向量 #n」两个通道标签，以及 RRF 分数；
- 查询词在正文中黄色高亮；
- 顶部延迟约 10–60 ms，并显示「x ms 嵌入 · y ms 检索」。

## 3. 核对 seekdb 证据

点击结果上方的「查看 seekdb 证据」。

预期：

- 全文索引显示 `TEXT RETRIEVAL SCAN`（绿色勾）；
- 向量索引显示 `VECTOR INDEX SCAN`（绿色勾）；
- 「实际 SQL」标签页展示本次执行的真实 SQL（CTE + MATCH + COSINE_DISTANCE）；
- 「EXPLAIN」标签页展示执行计划。

也可以直接查库：

```bash
cd deploy
docker compose exec seekdb mysql -uroot -P2881 -e \
  "SELECT COUNT(*) AS chunks FROM citeseek.chunks; SELECT title, status FROM citeseek.documents;"
```

## 4. 对比三种模式

切换到「仅全文」重复检索：只剩「全文」通道，语义改写的查询（例如「对话变长以后缓存占用膨胀怎么办」）可能漏召回。
切换到「仅向量」：只剩「向量」通道，专有名词（例如 `RRF`）的精确匹配会变弱。

预期：混合模式的 Hit@10 高于任一单通道，数据见 `docs/检索评测.md`。

## 5. 带引用问答

进入「带引用问答」，提问：

```
B+ 树和哈希索引分别适合什么查询？
```

预期：

- 生成 3–5 条结论，每条都是原文中的完整句子；
- 每条结论下方有「《文献名》第 N 页」引用按钮和章节标签；
- 点击引用，右侧抽屉打开对应页文本，并自动滚动、高亮该句；
- 顶部显示耗时与两条通道的候选数量。

## 6. 导出与原文

- 在回答卡片点「导出 Markdown」：下载的文件包含「## 出处」小节与脚注；
- 在文献详情页点「导出 BibTeX」：下载 `@misc{...}` 条目；
- 点「打开原始文件」：浏览器打开 PDF 并跳到当前页（`#page=N`）。

## 7. 数据留痕

```bash
tail -n 3 data/logs/retrieval.jsonl
```

预期：每次检索一行 JSON，包含 `query`、`mode`、`latency_ms`、`channel_counts`、`sql`、`top_hits`。

## 8. 一键复核（可选）

```bash
pip install httpx
python scripts/verify_library.py http://127.0.0.1:8080
python scripts/verify_search.py  http://127.0.0.1:8080
python scripts/verify_ask.py     http://127.0.0.1:8080
python scripts/evaluate.py       http://127.0.0.1:8080
```

四个脚本全部输出 `OK` 即通过。
