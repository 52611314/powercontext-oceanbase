# 技术证据：seekdb 在 CiteSeek 中的实际作用

> 记录时间：2026-10-27。环境：Windows 11 + Docker Desktop，seekdb 镜像 `oceanbase/seekdb:latest`（`5.7.25-OceanBase seekdb-v1.4.0.0`），嵌入模型 `BAAI/bge-small-zh-v1.5`（int8 ONNX，512 维）。

## 1. 存储与索引

```sql
CREATE TABLE chunks (
  id VARCHAR(64) NOT NULL PRIMARY KEY,
  doc_id VARCHAR(32) NOT NULL,
  page INT NOT NULL,
  section VARCHAR(255) NOT NULL DEFAULT '',
  chunk_no INT NOT NULL DEFAULT 0,
  text MEDIUMTEXT NOT NULL,
  char_start INT NOT NULL DEFAULT 0,
  char_end INT NOT NULL DEFAULT 0,
  embedding VECTOR(512) NOT NULL,
  FULLTEXT INDEX ft_text (text) WITH PARSER ik,
  VECTOR INDEX vidx_emb (embedding) WITH (distance=cosine, type=hnsw, lib=vsag),
  INDEX idx_doc (doc_id),
  INDEX idx_doc_page (doc_id, page)
);
```

实测建表结果（`SHOW CREATE TABLE`）确认：

- `FULLTEXT KEY ft_text (text) WITH PARSER ik PARSER_PROPERTIES=(ik_mode="smart")`
- `VECTOR KEY vidx_emb (embedding) WITH (DISTANCE=COSINE, TYPE=HNSW, LIB=VSAG, M=16, EF_CONSTRUCTION=200, EF_SEARCH=64)`

## 2. 混合检索：一条 SQL 同时走两路

应用实际执行的 SQL（参数化，`%s` 由 pymysql 绑定）：

```sql
WITH fts AS (
  SELECT c.id, c.doc_id, c.page, c.section, c.text,
         MATCH(c.text) AGAINST(%s IN NATURAL LANGUAGE MODE) AS score
  FROM chunks c
  WHERE MATCH(c.text) AGAINST(%s IN NATURAL LANGUAGE MODE)
  ORDER BY score DESC LIMIT %s
), vec AS (
  SELECT c.id, c.doc_id, c.page, c.section, c.text,
         COSINE_DISTANCE(c.embedding, %s) AS dist
  FROM chunks c
  WHERE 1=1
  ORDER BY dist APPROXIMATE LIMIT %s
)
SELECT 'fts' AS channel, id, doc_id, page, section, text, score, NULL AS dist FROM fts
UNION ALL
SELECT 'vector', id, doc_id, page, section, text, NULL, dist FROM vec
```

带筛选条件时，过滤会同时下推到两个分支（`AND c.doc_id IN (...)`），避免在应用层丢弃候选。

## 3. EXPLAIN 实测

```
|ID|OPERATOR                 |NAME       |EST.ROWS|EST.TIME(us)|
|0 |TEMP TABLE TRANSFORMATION|           |50      |2512        |
|1 |├─TEMP TABLE INSERT      |fts        |0       |1594        |
|2 |│ └─TEXT RETRIEVAL SCAN  |c(ft_text) |17      |1585        |
|3 |├─TEMP TABLE INSERT      |vec        |0       |919         |
|4 |│ └─VECTOR INDEX SCAN    |c(vidx_emb)|33      |902         |
|5 |└─UNION ALL              |           |50      |1           |
```

- 全文分支走 `TEXT RETRIEVAL SCAN`（IK 分词倒排索引）；
- 向量分支走 `VECTOR INDEX SCAN`（HNSW）；
- 带文档过滤时，向量分支变为 `VECTOR INDEX ADAPTIVE SCAN (PRE-FILTER)`，过滤条件下推、索引仍然生效。

接口返回中直接给出布尔判断，便于评审快速核对：

```json
{"indexes": {"fulltext": true, "vector": true}, "channel_counts": {"fts": 12, "vector": 20}}
```

## 4. 延迟实测

3 份示例资料、20 个文本块，21 条查询的 p50（容器内，含查询嵌入）：

| 模式 | p50 延迟 | 说明 |
| --- | --- | --- |
| hybrid | 5.2 ms | 两路候选 + Python 侧 RRF |
| fts | 4.5 ms | 仅全文通道 |
| vector | 4.5 ms | 仅向量通道 |

首次查询包含模型预热，会明显偏高（约 80–110 ms），报告数据均取预热后的结果。逐条结果见 `docs/检索评测.md`。

## 5. 引用可定位到页内字符

`POST /api/ask` 返回的每条结论都带有可定位的引用：

```json
{
  "text": "因此长上下文推理必须对 KV cache 做压缩或分页管理。",
  "citation": {
    "doc_id": "e7a2f6f4…",
    "page": 1,
    "section": "二、KV cache 的显存开销",
    "char_start": 606,
    "char_end": 621
  }
}
```

`char_start` / `char_end` 是相对该页文本的字符偏移，`GET /api/documents/{id}/pages/{page}` 返回同一份文本，前端按区间高亮即可。`scripts/verify_ask.py` 会自动校验每条引用的偏移与原文一致。

## 6. 复现步骤

```bash
cd deploy && docker compose up -d --build
cd .. && python scripts/make_samples.py
python scripts/verify_library.py http://127.0.0.1:8080
python scripts/verify_search.py http://127.0.0.1:8080
python scripts/verify_ask.py http://127.0.0.1:8080
```

`verify_search.py` 会把三种模式的通道统计与 EXPLAIN 写入 `docs/evidence/search-evidence.json`。

直接查库核对：

```bash
docker compose exec seekdb mysql -uroot -P2881 -e \
  "SELECT doc_id, page, section, LEFT(text, 30) AS preview FROM citeseek.chunks LIMIT 5"
```
